## 📑 C++ Module 05 ex01 : 要点まとめ

> **核心テーマ**: クラス間の相互作用における例外処理。Bureaucratの等級が書類の要求等級を満たしているかを判定し、適切にエラーを通知する。

---

### 1．課題の目的
* `Form` クラスを導入し、特定の等級を持つ `Bureaucrat` だけがその書類にサインできる仕組みを作る。
* サインが不可欠な場合に例外(`GradeTooLowException`)を投げ、呼び出し側で状況を把握できるようにする。

---

### 2．Formクラスの属性
書類には、その重要度に応じて「サインに必要な等級」と「実行に必要な等級」が設定される。

* **メンバ変数**
    * `const std::string name` : 書類名(定数)
    * `bool isSigned` : サインの有無(初期値はfalse)
    * `const int gradeToSign` : サインに必要な等級(定数)
    * `const int gradeToExecute` : 実行に必要な等級(定数)
* **例外のトリガー**
    * コンストラクタで設定された等級が1未満なら `GradeTooHighException`
    * 150を超えるなら `GradeTooLowException`

---

### 3．主要なメソッド
* **`beSigned(const Bureaucrat &b)`**
    * `Bureaucrat` オブジェクトを引数に取る。
    * `Bureaucrat` の等級が `gradeToSign` 以下(数値が小さい)なら `isSigned` をtrueにする。
    * 等級が足りない場合は `Form::GradeTooLowException` を投げる。

---

### 4．Bureaucratクラスの拡張
* **`signForm(Form &f)`**
    * `Bureaucrat` 側から書類にサインを試みるメソッド。
    * 内部で `f.beSigned(*this)` を呼び出す。
    * **成功時**：`<bureaucrat> signed <form>` と表示。
    * **失敗時**：`<bureaucrat> couldn’t sign <form> because <reason>` と表示。
    * ※ ここで例外を `catch` して、エラー理由(`e.what()`)を表示するのがポイント。



---

### 5．実装の注意点
* **定数メンバの初期化**
    * `name` や `grade` が `const` なので、初期化リストで値をセットする必要がある。
* **出力ストリーム**
    * `operator<<` をオーバーロードし、書類の名前、サイン状態、必要等級をすべて表示できるようにする。
* **例外の定義**
    * `Bureaucrat` と同様、`std::exception` を継承した内部クラスを定義する。

---

### 6．テストすべき項目

| テストケース | 期待される挙動 |
| :--- | :--- |
| **正常なサイン** | 等級の高い役人が、要求の低い書類にサインできるか。 |
| **等級不足のサイン** | 等級の低い役人がサインしようとした際、適切なエラーメッセージが出るか。 |
| **Form自体の例外** | 書類作成時に 0 や 151 の等級を指定して例外が発生するか。 |
| **二重サインの確認** | 既にサインされた書類の状態が正しく保持されるか。 |

---

### 7．まとめ

| 項目 | 内容 |
| :--- | :--- |
| **主要技術** | クラス間連携、定数メンバの初期化リスト、例外の再スロー/キャッチ |
| **設計の鍵** | `Form::beSigned` は例外を投げ、`Bureaucrat::signForm` はその例外を処理してユーザーに通知する |
| **安全性** | 権限のない操作が確実にブロックされ、その理由がログ（標準出力）に残る |
