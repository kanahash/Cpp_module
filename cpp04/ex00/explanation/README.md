## 🐾 C++ Module 04 ex00 : 要点まとめ

> **核心テーマ**: オブジェクト指向プログラミングの最重要概念の1つである「ポリモーフィズム(多態性)」と、それを実現するための `virtual`(仮想関数) の役割を理解すること。

---

### 1．課題の目的
基底クラス(`Animal`)から派生クラス(`Dog`, `Cat`)を作成し、基底クラスのポインタを使って派生クラスを操作した際に、正しい挙動(鳴き声など)が選択される仕組みを学ぶ。

---

### 2．ポリモーフィズム(多態性)とは
同じ関数呼び出し(例：`makeSound()`)が、オブジェクトの実際の型に応じて異なる動作をすることを指す。

* **期待される挙動**
    * `Animal` ポインタが `Dog` を指していれば「ワン！」、`Cat` を指していれば「ニャー！」と鳴くこと。



---

### 3．virtual キーワードの重要性
ポリモーフィズムを実現するためには、基底クラスの関数に `virtual` をつける必要がある。

* **仮想関数(Virtual Function)**
    * 基底クラスで `virtual` 宣言された関数は、実行時に「実際の型」を確認して、派生クラスで再定義(オーバーライド)された関数を呼び出す（**動的結合**）。
* **virtualがない場合**
    * コンパイラはポインタの型(`Animal`)だけを見て判断するため、中身が `Dog` であっても `Animal` の鳴き声が呼び出されてしまう（**静的結合**）。

---

### 4．仮想デストラクタの必須性
**最も重要な注意点**。基底クラスのデストラクタには必ず `virtual` をつける必要がある。

* **理由**
    * `Animal* meta = new Dog();` のように生成したオブジェクトを `delete meta;` した際、デストラクタが `virtual` でないと、`Animal` のデストラクタしか呼ばれない。
    * 結果として、`Dog` 特有のメモリ領域が解放されずに**メモリリーク**が発生する。



---

### 5．WrongAnimal / WrongCat クラスの役割
比較のために「あえて `virtual` を使わないクラス」を作成する。

* `WrongAnimal` の `makeSound()` に `virtual` を付けずに実装すると、たとえ `WrongCat` を代入しても `WrongAnimal` の音しか出ないことを確認する。
* これにより、`virtual` がポリモーフィズムにおいていかに不可欠かを体感する。

---

### 6．実装のルール
* **OCCF(直交標準形)の遵守**
    * 各クラス(`Animal`, `Dog`, `Cat`)は Module 02 で学んだ4要素を実装する必要がある。
* **メンバ変数**
    * `std::string type` を持ち、コンストラクタで適切な値("Dog"など)をセットする。
* **出力**
    * 各コンストラクタ・デストラクタが呼ばれたことがわかるようにメッセージを表示する。

---

### 7．テストすべき項目

| テストケース | 期待される挙動 |
| :--- | :--- |
| **標準的な多態性** | `Animal* j = new Dog();` -> `j->makeSound()` で Dog の音が出る。 |
| **デストラクタの連鎖** | `delete j;` した際に Dog と Animal 両方のデストラクタが呼ばれる。 |
| **Wrong系のテスト** | `WrongAnimal* k = new WrongCat();` -> `k->makeSound()` で WrongAnimal の音が出る。 |

---

### 8．まとめ

| 項目 | 内容 |
| :--- | :--- |
| **主要技術** | サブタイピング・ポリモーフィズム、仮想関数（virtual） |
| **絶対ルール** | 基底クラスのデストラクタを `virtual` にすること |
| **設計の鍵** | ポインタの型ではなく、実体の型に応じた挙動の制御 |
