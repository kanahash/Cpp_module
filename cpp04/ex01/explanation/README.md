## 🧠 C++ Module 04 ex01 : 要点まとめ

> **核心テーマ**: 「ディープコピー(深層コピー)」の概念と、複雑なオブジェクトにおける「メモリ管理」を正しく行うこと。

---

### 1．課題の概要
* `Dog` クラスと `Cat` クラスに、新しいクラス `Brain` をメンバ変数として持たせる。
* `Brain` は `std::string ideas[100]` という配列を持ち、`new` によって動的に生成される。

---

### 2．ディープコピー(Deep Copy)の重要性
クラスがポインタ(`Brain*`)をメンバに持つ場合、デフォルトのコピー(シャローコピー)では重大な問題が発生する。

* **シャローコピー(浅いコピー)**
    * ポインタの「アドレス」だけをコピーする。
    * 2つのオブジェクトが同じ `Brain` を指してしまい、一方で `delete` するともう一方が壊れる（**二重解放 / Double Free** の原因）。
* **ディープコピー(深いコピー)**
    * 新しく `Brain` を `new` し、中身の配列データを一つずつコピーする。
    * オブジェクトごとに独立した `Brain` を持つため、安全に操作できる。



---

### 3．実装のポイント (Dog / Cat クラス)
* **コンストラクタ**: `new Brain()` を行い、自分専用の脳を生成する。
* **デストラクタ**: 自分が作成した `Brain` を `delete` する。
* **コピーコンストラクタ / コピー代入演算子**
    * 単なるアドレスの代入ではなく、相手の `Brain` の中身をコピーして新しい `Brain` を作るように実装する（ディープコピー）。

---

### 4．仮想デストラクタの再確認
ex00に引き続き、基底クラス `Animal` のデストラクタが `virtual` であることが不可欠。

* **メモリリークの危険性**
    * `Animal* j = new Dog(); delete j;` とした時、`Animal` のデストラクタしか呼ばれないと、`Dog` が持っている `Brain` が解放されず、メモリリークが発生する。



---

### 5．テストすべき項目

| テストケース | 期待される挙動 |
| :--- | :--- |
| **配列による一括生成/削除** | `Animal*` の配列（半分 Dog, 半分 Cat）を作成し、ループで一気に `delete` してリークがないか。 |
| **ディープコピーの検証** | `Dog a; Dog b = a;` とした後、`a` の脳を書き換えても `b` の脳に影響がないか。 |
| **リークチェック** | `valgrind` などのツールを使用して、すべてのメモリが適切に解放されているか。 |

---

### 6．まとめ

| 項目 | 内容 |
| :--- | :--- |
| **主要技術** | ディープコピー、動的メモリ確保（new/delete） |
| **注意点** | OCCF（Canonical Form）における適切なコピー処理の実装 |
| **設計の鍵** | 「脳（Brain）」の所有権を各動物が独立して持つこと |
