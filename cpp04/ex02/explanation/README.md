## 🚫 C++ Module 04 ex02 : 要点まとめ

> **核心テーマ**: 「抽象クラス(Abstract Class)」と「純粋仮想関数(Pure Virtual Function)」を理解し、不適切なインスタンス化を防ぐ設計を学ぶ。

---

### 1．課題の概要
* ex01で作成した `Animal` クラスを、インスタンス化できない**「抽象クラス」**に変更する。
* `Dog` や `Cat` はこれまで通りインスタンス化できるが、概念としての `Animal` は実体を持てないように制限をかける。

---

### 2．純粋仮想関数(Pure Virtual Function)
抽象クラスを作るために、メンバ関数の宣言に `= 0` をつける。これを「純粋仮想関数」と呼ぶ。

* **書き方**
  `virtual void makeSound() const = 0;`
* **意味**
    * 基底クラス(`Animal`)では関数の「定義(中身)」を持たず、派生クラスに対して**「必ずこの関数をオーバーライドせよ」という契約**を強制する。
    * 派生クラスでこの関数を実装（オーバーライド）しない限り、その派生クラスもインスタンス化できない。



---

### 3．抽象クラス(Abstract Class)
1つ以上の純粋仮想関数を持つクラスは、自動的に「抽象クラス」となる。

* **インスタンス化の禁止**
    * 抽象クラスは `new Animal()` や `Animal a;` のように実体を作ろうとすると、**コンパイラエラー**になる。
* **存在理由**
    * 「動物(`Animal`)」という抽象的な概念が、単体で実体として鳴き声を出したり存在したりするのは不自然である。
    * 具体的な「犬」や「猫」を通じてのみ存在を許すことで、より堅牢で論理的な設計になる。



---

### 4．ポリモーフィズムの継続
抽象クラスになっても、**「型としての利用」は可能**である。

* `Animal* j = new Dog();` (ポインタ)や `Animal& k = cat;` (参照)として扱うことは引き続き可能。
* これにより、ex00/ex01で学んだポリモーフィズム(多態性)を維持したまま、より安全な設計ができる。

---

### 5．テストすべき項目

| テストケース | 期待される挙動 |
| :--- | :--- |
| **インスタンス化の拒否** | `Animal a;` や `new Animal()` を記述した際に、コンパイルエラーが発生するか。 |
| **派生クラスの動作** | `Dog` や `Cat` は通常通り生成・削除でき、鳴き声も正しく出るか。 |
| **ポリモーフィズムの確認** | `Animal*` ポインタを介して `Dog` の脳（`Brain`）や鳴き声が正しく操作できるか。 |

---

### 6．まとめ

| 項目 | 内容 |
| :--- | :--- |
| **主要技術** | 純粋仮想関数（`= 0`）、抽象クラス |
| **設計のメリット** | 概念のみのクラスが実体化されるミスを防ぎ、継承先での実装を強制できる |
| **実装の鍵** | `Animal` クラスの特定の関数（例：`makeSound`）を純粋仮想にする |
