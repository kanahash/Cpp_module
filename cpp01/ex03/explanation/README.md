## 🧠 C++ Module 01 ex03: 要点まとめ
 →「ポインタ」と「参照」を、実際のクラス設計の中でどのように使い分けるかを学ぶ

### 1．課題の構造
 →武器クラス(`Weapon`)と、それを使用する人間クラス(`HumanA`、`HumanB`)を作成する

* **Weapon**：`type`(文字列)を持ち、`getType`/ `setType`を提供する
* **HumanA**：生成時に必ず武器を持たされる。途中で武器を手放すことはない
* **HumanB**：生成時に武器を持っていない場合がある。途中で武器を持ち替えたり、装備したりする

### 2．HumanAとHumanBの決定的な違い(参照vsポインタ)
 →クラスのメンバ変数に「他のオブジェクト」を保持する場合、その性質によってポインタと参照を使い分ける

| クラス | 武器の保持方法 | 理由 |
| :--- | :--- | :--- |
| **HumanA** | 参照 (`Weapon &`) | **「武器が必須」**だから。参照はヌル（NULL）にできず、初期化時に必ず対象が必要。 |
| **HumanB** | ポインタ (`Weapon *`) | **「武器が任意（ヌル可）」**だから。ポインタは後から代入したり、NULLを指したりできる。 |

### 3．実装の注意
#### ➀ HumanAのコンストラクタ
→HumanAはメンバ変数に「参照」を持つため、**初期化リストでの初期化が必須**。コンストラクタの本体(`{}`の中)で代入することはできない。

#### ➁ HumanBの柔軟性
→HumanBは武器を持っていない状態で生成されるため、初期化は`NULL`にする。武器を装備するための`setWeapon`メソッドが必要。

#### ③ 武器の「型」の一貫性
→`Weapon`クラスの`getType`は、`const std::string&` を返すように設計するのが一般的である。これにより、不要な文字列のコピーを避けつつ、安全に値を参照できる。

### 4．参照とポインタの使い分け基準
* **参照(&)を使うべき時**
    * 対象が絶対に存在する(NULLにならない)
    * 一度決めた対象を途中で変更しない(再バインド不可)
* **ポインタ(*)を使うべき時**
    * 対象がいない状態(NULL)がありえる
    * 途中で指す対象を切り替えたい

### 5．まとめ

| 特徴 | HumanA (Reference) | HumanB (Pointer) |
| :--- | :--- | :--- |
| 武器の有無 | 常に持っている | 持っていないことがある |
| 初期化方法 | コンストラクタ（必須） | setWeapon（任意） |
| 再代入 | 不可能 | 可能 |
| 安全性 | 高（NULLを考慮不要） | 中（NULLチェックが必要） |

> ※「不変で必須な関係なら参照、可変で不確実な関係ならポインタ」

}
