## 🛠️ C++ Module 01 ex04: 要点まとめ（Sed is for losers）

> **核心テーマ**: 標準ライブラリのファイル入出力（fstream）と文字列操作を組み合わせ、C++における「ストリーム」という概念と堅牢なエラーハンドリングを習得する。

---

### 1. 課題の目的
指定されたファイル内の特定の文字列（s1）を、別の文字列（s2）に置換し、その結果を新しいファイル（`.replace` 拡張子）に保存するプログラムを作成する。

* **禁止事項と推奨設計**:
    * `std::string::replace` メンバ関数の使用は禁止されていないが、教育的意図から **ループと `find` を使ったアルゴリズム自体の実装** が求められる。
    * **理由**: `std::string::replace` は範囲指定の関数であり、結局 `find` で位置を特定する必要がある。また、自前で実装することでインデックス管理やメモリ移動の挙動を深く理解できる。

---

### 2. ストリーム（Stream）とは
「データの流れる川」のような概念。ファイルの内容を一度に全て読み込む巨大な塊としてではなく、連続したデータの流れとして扱うための抽象的な仕組み。



#### A. イメージと特徴
1. **データの通り道（抽象化）**:
    * 利点：相手が誰であっても、同じ方法でデータをやり取りできる。
    * ファイルなら `fstream`、画面/キーボードなら `iostream`、文字列なら `stringstream`。
    * 開発者は、相手が物理的に何であるかを意識せず、`<<` や `>>` という共通操作で扱える。
2. **逐次処理**:
    * データを「先頭から順番に」処理する。
    * 1文字ずつ、あるいは1行ずつ（`std::getline`）順番に取り出し、加工して次のデータへ流す。

#### B. ex04 における役割
2つのストリームを同時に使い「加工（置換）」を行う。
1. **`std::ifstream` (Input File Stream)**: ファイルからデータを「吸い出す」。
2. **`std::ofstream` (Output File Stream)**: 加工済みのデータを新しいファイルへ「流し込む」。



#### C. ストリームを使用するメリット
1. **メモリの節約**: 巨大なファイルを一度にメモリへ読み込むとパンクするが、1行ずつ処理すればメモリ消費を最小限に抑えられる。
2. **状態管理が容易**: 「どこまで読んだか」というポインタ情報や、エラー状態（フラグ）が備わっている。
    * `ifs.eof()`: 終端に達したか。
    * `ifs.fail()`: 読み取りエラーが発生したか。

---

### 3. 置換アルゴリズム
`std::string::find` を使って位置を特定し、新しい文字列を構築する。

#### アルゴリズムのフロー
1. 内容を読み込む。
2. `line.find(s1, pos)` で `s1` の出現位置を探す。
3. 見つかったら、そこまでの部分を結果に追加し、`s2` を追加する。
4. **重要**: 検索位置を **「置換した s1 の後ろ」** にずらす。
5. 見つからなくなるまで繰り返す。

---

### 4. 実装における注意点
1. **空文字（Empty String）への対応**:
    * `s1` が空の場合、無限ループに陥る可能性がある。最初にチェックしてエラーを出すのが堅牢な設計。
2. **置換後の検索開始位置**:
    * 次の検索は「置換した s2 の後ろ」から開始する必要がある。そうしないと、`s1` が `s2` の一部だった場合に無限ループが発生する。
3. **エラーハンドリング**:
    * 引数の数、`ifs.is_open()` によるオープン確認、ディレクトリ指定による失敗などを網羅する。

---

### 5. テストで重要な点

#### A. 無限ループのチェック（最優先）
* **例**: `a` を `aa` に置換するケース。
* **ポイント**: 検索開始位置を正しく進めていないと、新しく作った `a` を再び置換し続けて終わらなくなる。

#### B. 空文字のハンドリング
* `s1` が空：無限ループの温床。
* `s2` が空：文字の削除として機能すべき。
* ファイル名が空：オープンエラーの適切な処理。

#### C. ファイル操作のエラー処理
* 存在しないファイル、権限がない（`chmod 000`）、ディレクトリを指定、ディスクフル等。

#### D. 特殊ケース
* **連続置換**: `aaaa` に対して `aa` を `b` に置換して `bb` になるか。
* **改行コード**: 最終行の改行の有無。
* **大規模ファイル**: ストリームによる逐次処理が正しく行われているか。

#### E. チェックリスト

| テストケース | 入力例 | 期待される挙動 |
| :--- | :--- | :--- |
| 基本 | `test.txt "hello" "world"` | hello が world に変わる |
| 無限ループ防止 | `test.txt "a" "aa"` | 1回ずつ置換され、ループしない |
| 削除テスト | `test.txt "bad" ""` | bad が消える |
| s1未発見 | `test.txt "none" "exist"` | 元のファイルと同じ内容が出力 |
| 空のs1 | `test.txt "" "something"` | エラー表示（またはフリーズしない） |
| 権限エラー | `unreadable.txt "a" "b"` | エラーログを表示 |

---

### 6. まとめ

| 項目 | 内容 |
| :--- | :--- |
| **本質** | データの連続的な流れを扱うための抽象的な「管」。 |
| **操作** | `<<` (挿入) と `>>` (抽出) という直感的な演算子。 |
| **利点** | メモリ効率が良く、デバイスを問わず同じ書き方ができる。 |

**「ファイルを開く」→「データがなくなるまで繰り返す」→「ファイルを閉じる」**
という一連の作法がストリーム操作の基本。
