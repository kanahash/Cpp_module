## 1. 核心概念：`new[]` と `delete[]` の厳格なペアリング

この課題の目的は、`N` 体のゾンビをヒープ上に一括で確保し、その後、確実に一括で解放する関数を実装することです。

### 🚨 最重要ポイント：`delete[]` の使用

| 関数・操作 | 役割 | C++の演算子 |
| :--- | :--- | :--- |
| **生成側** | $N$ 体のゾンビをヒープに生成し、先頭ポインタを返す。 | `new Zombie[N]` |
| **解放側** | 受け取った配列を操作後、メモリを解放する。 | `delete[] ポインタ` |

* **`delete[]` の役割**: `new[]` で確保したメモリを解放する際、`N` 個すべてのオブジェクトの **デストラクタを順番に呼び出す** ことを保証します。

* **単なる `delete` の危険性**:
    * 最初の1体のデストラクタしか呼ばれず、残り $N-1$ 体のクリーンアップが行われません。
    * 結果として、**メモリリーク** や未定義動作（プログラムの異常終了）を引き起こします。

## 2. 実装上のテクニックと課題解決

### ① 配列の生成とコンストラクタの制約
`new Zombie[N]` を実行するとき、C++のルールにより、コンパイラは $N$ 個の `Zombie` の **引数なしのデフォルトコンストラクタ** を呼び出そうとします。

* **課題**: `new[]` では引数付きコンストラクタ（例: `new Zombie("Name")`）を呼べません。
* **対策**:
    1.  `Zombie` クラスに引数なしのコンストラクタ（デフォルトコンストラクタ）を用意する。
    2.  `zombieHorde` 関数内で、生成後にループを回し `horde[i].setName(name);` のように、各ゾンビの名前を個別に設定する必要があります。

### ② ポインタの返却と利用
* `zombieHorde` は、ヒープ上の配列の先頭要素へのポインタを返します。
* 戻り値はポインタですが、C言語の配列と同じように **`myHorde[i]`** の形式でアクセスして操作できます。

## 3. 合格のための検証（メモリ安全性）

この課題はメモリリークがないことがすべてです。以下の検証を必須とします。

### ❶ デストラクタのログ確認
* `Zombie` のデストラクタにログ（例: `<name>: died`）を仕込みます。
* `delete[]` を呼んだ際に、$N$ 体分すべてのログが正確に出ることを確認し、**全オブジェクトのデストラクタが呼ばれている** ことを視覚的に証明します。

### ❷ Valgrind の使用
* プログラムを実行後、`valgrind` などのツールを使用し、**メモリリークがないこと**（`0 bytes in 0 blocks`）を必ず確認します。これが最終的な合格基準です。

// main 関数での利用と解放のイメージ
int N = 100;

// ... 操作 ...

// 解放: メモリリークを避けるため、必ず delete[] で解放し、デストラクタをN回実行させる
