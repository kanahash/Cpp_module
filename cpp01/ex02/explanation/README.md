## 🧠 C++ Module 01 ex02: 要点まとめ（ポインタと参照）

### 1. 課題の構造と目的

この課題では、以下の3つの要素を定義し、それらのアドレスと値を比較します。

* **定義する3要素**:
    1.  `std::string str`: データを格納する**元の変数**。
    2.  `std::string* stringPTR`: `str` の**アドレス**を格納する**ポインタ**。
    3.  `std::string& stringREF`: `str` の**別名（エイリアス）**となる**参照**。

* **目的**: ポインタと参照がどちらも元の変数と同じデータを指していることを証明し、それぞれのアクセス方法をマスターすること。

### 2. ポインタ（Pointer: `*`）の役割

ポインタはメモリ上の**「アドレス（番地）」**を格納するための変数です。

| 項目 | 詳細 | 構文例 |
| :--- | :--- | :--- |
| **定義** | 変数の型に `*` をつけて宣言。 | `std::string* stringPTR;` |
| **格納値** | 元の変数 `str` の**メモリアドレス**。 | `stringPTR = &str;` |
| **値へのアクセス** | **間接参照演算子 (`*`)** を使用。 | `std::cout << *stringPTR;` |
| **アドレス** | `stringPTR` 自体のアドレスは `str` とは別。格納しているアドレスは `str` と同じ。 | `std::cout << stringPTR;` (格納アドレス) |

### 3. 参照（Reference: `&`）の役割

参照は、既存の変数につけられた**「別名（エイリアス）」**のことです。一度初期化すると、元の変数と同じものとして振る舞います。

| 項目 | 詳細 | 構文例 |
| :--- | :--- | :--- |
| **定義** | 変数の型に `&` をつけて宣言。 | `std::string& stringREF = str;` |
| **初期化の義務** | **定義時に必ず**元の変数に結びつけなければならない。 | `std::string& stringREF = str;` |
| **値へのアクセス** | **特別な演算子は不要**。元の変数と同じように扱える。 | `std::cout << stringREF;` |
| **アドレス** | `stringREF` のアドレスは、元の変数 `str` のアドレスと**完全に一致する**。 | `std::cout << &stringREF;` |

### 4. 注意点と実装のポイント

#### ➀ ポインタと参照の「型」を厳密に扱う

| 要素 | 型 |
| :--- | :--- |
| **元の変数(値)** | `std::string` 型 |
| **ポインタ(アドレス)** | `std::string*` 型 |
| **参照(別名)** | `std::string&` 型 |

#### ➁ ポインタと参照の「アクセス方法」の違い
　→アドレスと値を出力する際に、どの演算子を使うか(または使わないか)が重要

| 取得したいもの | 元の変数 (`str`) | ポインタ (`stringPTR`) | 参照 (`stringREF`) |
| :--- | :--- | :--- | :--- |
| **値** | `str` | `*stringPTR` (間接参照) | `stringREF` |
| **アドレス** | `&str` | `stringPTR` | `&stringREF` |

#### ③ 参照の初期化義務と再バインド禁止
* **初期化の義務**
　→参照は定義時に必ず初期化(どの変数の別名にするか指定)しなければならない
　初期化されていない参照は存在しない
　・OK→`std::string& stringREF = str;`
　・NO→`std::string& stringREF;`

* **再バインドの禁止**
　→一度strに結びつけた参照は、後から別の変数に付け替えることはできない
　　・`stringREF = "新しい値";`
　　　→参照が指す先のstrの値を変更するだけで、stringREFが別の変数を指すようにはならない

#### ④ アドレス比較による証明
　→この課題において最も重要な点：「3つの表現が、メモリ上の全く同じ場所を指している」こと
　→出力結果として、3つのアドレス(`&str`, `stringPTR`, `&stringREF`)が完全に一致していることを証明する
* **証明すべきこと**：`&str == stringPTR` かつ `&str == &stringREF` であること

#### ⑤ constの推奨(堅牢なコードとして)
　→課題の要件ではないが、より堅牢なコードとして、ポインタや参照を関数に渡す際、値を変更しないのであればconstをつけるべきである

* **推奨**：`void print_addresses(const std::string& str, const std::string* ptr, const std::string& ref);`
　→これにより、関数内でstrやrefの値を意図せず変更することを防ぐ

### 5. 必須の検証ポイント

#### ➀ メモリアドレスの比較
　→3つの表現が、全て同じ場所を指していることを示す
* `&str` : 元の変数のアドレス
* `stringPTR` : ポインタが格納しているアドレス(アドレス演算子不要)
* `&stringREF` : 参照のアドレス(参照自体にアドレス演算子を適用)

$$\text{Address}(\text{str}) = \text{Address}(\text{stringPTR}) = \text{Address}(\text{stringREF})$$

#### ➁ 値の比較
　→3つの表現が、全て同じ値を出力することを示す
* `str` : 元の変数名
* `*stringPTR` : ポインタの間接参照
* `stringREF` : 参照(別名)

$$\text{Value}(\text{str}) = \text{Value}(\text{*stringPTR}) = \text{Value}(\text{stringREF})$$

### 6. まとめ

| 特徴 | ポインタ (`*`) | 参照 (`&`) |
| :--- | :--- | :--- |
| **格納するもの** | メモリアドレス | 元の変数自身 (別名) |
| **ヌル（NULL）** | ヌルポインタにできる (`NULL` / `nullptr`) | ヌルにできない (常に有効な対象を参照) |
| **再バインド** | 可能 (別の変数のアドレスを代入できる) | 不可能 (初期化時に結びついた変数から変更できない) |
| **アクセス** | `*` 演算子が必要 | 元の変数と同じように直接アクセス |

※この違いの理解が重要
　**「ポインタはアドレスを操作するもの」**
　**「参照は変数を直接操作するための別名」**

4-➀
```cpp
#include <string>
#include <iostream>

void    print_addresses(const std::string& str, const std::string* ptr, const std::string& ref)
{
    // strのアドレスを取得
    std::cout << "str Address : " << &str << std::endl;
    // ptrが保持するアドレス（strのアドレス）
    std::cout << "PTR Address : " << ptr << std::endl;
    // refのアドレスを取得（strのアドレスと一致）
    std::cout << "REF Address : " << &ref << std::endl;
}
