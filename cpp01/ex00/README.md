# C++ - Module 01: 要点まとめ（Memory Allocation）

このモジュールの核心は、C言語の `malloc/free` を脱却し、C++における **Stack（スタック）** と **Heap（ヒープ）** の使い分け、および **`new/delete`** の作法を習得することにあります。

---

## 1. Stack（スタック）と Heap（ヒープ）の決定的な違い

オブジェクトを「いつ、どちらで作成すべきか」を判断する能力が問われます。

### ■ Stack（スタック）割り当て：`randomChump`
関数の中で `Zombie zombie(name);` と宣言する方法です。

* **寿命**: その関数（スコープ）が終了すると、自動的にデストラクタが呼ばれて消滅します。
* **利点**: 高速。メモリ解放を意識する必要がなく、リークの心配がありません。
* **欠点**: 
    * 関数外にオブジェクトを持ち出せない（関数終了時に破棄されるため）。
    * メモリ容量が小さく、巨大なデータや動的なサイズ変更には向きません（スタックオーバーフローのリスク）。
* **用途**: **「その関数の中だけで使い切る」** 一時的な利用に最適です。



### ■ Heap（ヒープ）割り当て：`newZombie`
`new` キーワードを使い、`Zombie* zombie = new Zombie(name);` と宣言する方法です。

* **寿命**: **`delete` を呼ぶまで** 生き続けます。
* **利点**: 
    * 関数が終わっても消えないため、ポインタを `return` して他の場所で使い続けられます。
    * システム全体の空きメモリを広く利用でき、巨大なデータも扱えます。
* **欠点**: 手動で `delete` しないと **メモリリーク** になります。
* **用途**: **「オブジェクトを関数の外に持ち出したい」**、**「生存期間を自由にコントロールしたい」** 場合に使用します。



---

## 2. `new` キーワードの使い方
ヒープ領域にメモリを確保し、オブジェクトの **コンストラクタを呼び出す** ための演算子です。

### ① 基本構文
| パターン | 構文（生成） | 構文（解放） |
| :--- | :--- | :--- |
| **単一オブジェクト** | `Zombie* z = new Zombie("Foo");` | `delete z;` |
| **配列の生成** | `Zombie* horde = new Zombie[10];` | `delete[] horde;` |

* メンバ関数へのアクセスには `->` アロー演算子を使用します。

### ② `new` が裏側で行っていること
単なるメモリ確保（malloc）と異なり、以下の3工程を自動で行います。
1.  **メモリの確保**: ヒープから必要なバイト数を探す。
2.  **コンストラクタの呼び出し**: 確保した領域でコンストラクタを実行し、初期化する。
3.  **アドレスの返却**: 正しい型のポインタとしてアドレスを返す。



---

## 3. `delete` と `delete[]` の厳格な使い分け
42の評価において、この使い分けのミスは致命的（メモリリーク/未定義動作）と見なされます。

| 確保の方法 | 解放の方法 | 理由 |
| :--- | :--- | :--- |
| `new Zombie()` | `delete z;` | 1つのインスタンスのデストラクタを呼ぶため |
| `new Zombie[N]` | `delete[] z;` | **全要素（N個分）** のデストラクタを順番に呼ぶため |



---

## 4. 注意点：メモリリークの発生条件
以下のようなケースでは、メモリにアクセスする手段が失われ、リークが発生します。
* `delete` を呼ぶ前に、ポインタ変数に別の値を代入したとき。
* `delete` を呼ぶ前に、ポインタ変数がスコープを抜けたとき。

> **Key Rule**: 「その関数の中で使い切るなら Stack。外に持ち出すなら Heap」
