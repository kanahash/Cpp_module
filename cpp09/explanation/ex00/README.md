# C++ Module 09 - ex00: Bitcoin Exchange 攻略メモ

## 📌 プログラムの全体像
本課題の目的は、**2つのファイル（DBと入力）を突き合わせ、ビットコインの価値を計算する**ことです。

1.  **data.csv (提供DB)**: 日付と当時のビットコインレートの履歴。
2.  **input.txt (評価用)**: ユーザーが計算したい「日付 | 数量」のリスト。

---

## 🔑 最重要ルール：過去への遡り
入力された日付がDBに存在しない場合、**「その日より前（過去）で、最も近い日付」**のレートを使用します。
> ⚠️ **注意**: 未来の日付のレートを使用してはいけません。

---

## 🛠 実装に不可欠な3つの技術

### 1. `std::map<std::string, float>` の活用
本課題に最適なコンテナです。
* **自動ソート**: キー（日付文字列）を入れるだけで、自動的に日付順に整列されます。
* **探索アルゴリズム**: `lower_bound` や `upper_bound` を使うことで、要件である「過去の直近データ」を高速に見つけることができます。



### 2. 文字列のパースとバリデーション
入力された `"2011-01-03 | 3"` を正しく分解して検証する必要があります。
* **区切り文字**: DBは `,`（カンマ）、入力ファイルは `|`（パイプ）。
* **日付チェック**: 存在しない月（13月）や、うるう年でない年の2月29日などはエラーにする必要があります。
* **数値チェック**: 0〜1000の範囲内か、正の数かを厳密にチェック。



### 3. エラー処理の作法
1行のエラーでプログラムを止めてはいけません。
* 不正な行を見つけたら **エラーメッセージを表示して、即座に次の行へ移動** するループ処理が必要です。

---

## 🧪 テストすべき項目一覧

| テスト項目 | 期待される動作 |
| :--- | :--- |
| **引数なしで実行** | `Error: could not open file.` と表示して終了 |
| **DBファイル欠如** | 適切にエラー表示（`try-catch` で致命的エラーを捕捉） |
| **未来すぎる日付** | DB内の最新（最後）のレートが適用されること |
| **最古の日付より前** | 「データなし」としてエラー処理 |
| **負の数値** | `Error: not a positive number.` |
| **1000を超える数値** | `Error: too large a number.` |
| **不正な日付形式** | `Error: bad input => 2001-42-42` |
| **空行・異常文字** | クラッシュせずにスキップ、またはエラー表示 |

## 💡 学習のアドバイス

### Q. 日付を文字列のまま比較していいの？
**A. はい、大丈夫です。**
`"YYYY-MM-DD"` 形式は、文字列として比較しても日付の前後関係が崩れません。
* 例: `"2011-01-01" < "2011-01-02"` は `true`
わざわざ `struct tm` 等に変換しなくても、`std::map` のキーとしてそのまま使えます。

### Q. Containerの禁止ルールについて
> **Warning**: The container(s) you use to validate this exercise will no longer be usable for the rest of this module.

「ex00で使った武器は、ex01やex02では封印される」というルールです。
* ex00で `std::map` を使った場合、ex01/ex02では `std::list`, `std::vector`, `std::deque`, `std::stack` 等、別のコンテナを選択しなければなりません。

---

## 🚀 実装の流れ（ヒント）
1.  `data.csv` を読み込み、`std::map` に全データを格納する。
2.  `input.txt` を1行ずつ読み込むループを作る。
3.  各行をパースし、エラーがあれば表示して `continue`。
4.  エラーがなければ、`map` から適切なレートを取得して計算結果を表示する。
